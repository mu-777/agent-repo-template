# web-share-assets — OGP・共有画像・ファビコン

ホスティング先を問わず共通。検索での見え方は [web-seo](../web-seo/SKILL.md)、公開作業は [web-deploy](../web-deploy/SKILL.md)。

---

## 0. 先に受け入れる不変条件(ここを疑って時間を溶かさない)

1. **クローラは JS を実行しない。** アプリ内の言語切替や実行時の `<meta>` 書き換えは**共有プレビューに一切反映されない**。SNS カードに出したいものは**ビルド時の静的タグ**に置く。
2. **OGP は「1 URL = 1 枚」。** 閲覧者の言語や状態に応じて SNS 側が出し分けることはできない。ロケール別に確実に出し分けたいなら**ロケール別の静的 HTML(別 URL)**が要る。
3. **どの SNS の web intent も画像を運べない。** 受け取るのは text と url だけで、画像のパラメータは存在しない。**「やり方があるはず」と再調査しない。** ユーザーの成果物画像を投稿に載せたいなら「**画像をコピー / 保存 → 貼り付け**」を案内する経路しかない。
4. **`navigator.share({ files })` は環境によって本文が落ちる。** 画像とテキストの同時共有を前提にした設計にしない。
5. **静的ホスティングでも「URL ごとに違う OGP」は技術的には作れる**(配信レイヤに処理を生やせる構成なら)。作らないと決めているなら、**理由を「技術的に不可能」と説明しない**(嘘になり、次に読む人が再検討できない)。線引きは決定記録に書く。

## 1. `<head>` に置くタグ

```html
<meta property="og:type"        content="website" />
<meta property="og:site_name"   content="<アプリ名>" />
<meta property="og:title"       content="<短いブランド名 or ページ名>" />
<meta property="og:description" content="<初対面の 1 行>" />
<meta property="og:url"         content="<絶対 URL>" />
<meta property="og:locale"      content="<実表示の言語>" />
<meta property="og:image"       content="<絶対 URL>" />
<meta property="og:image:type"   content="image/png" />
<meta property="og:image:width"  content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:alt"   content="<画像の内容>" />
<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title" /><meta name="twitter:description" /><meta name="twitter:image" />
```

- **`og:image` は絶対 URL**(相対を解決するかはサービスごとに違い、一次情報で確認できないことがある)。`og:image:width` / `height` を添えるとカードの初回描画が安定する。
- **`<title>` と `og:title` は別物でよい。** 前者は検索向けにキーワードを含む記述、後者は SNS カード向けに短いブランド名、という使い分けは一般的。
- **`og:description` と `meta[name=description]` はキーを分ける**(→ [web-seo](../web-seo/SKILL.md) §2)。
- SPA でページごとにカードを変えたいなら、**それは静的 HTML が 1 枚である限り不可能**。§0-1。

## 2. OG 画像 — 寸法と安全域

| 項目 | 値 | 備考 |
|---|---|---|
| 基本寸法 | **1200 × 630**(1.91:1) | `summary_large_image` の標準。ここから外れる理由が無ければこれ |
| 安全域 | **中央 630 × 630 に収まるように組む** | サービスによっては正方形にクロップされる。**左テキスト / 右ビジュアルの横並びにすると両方切れる** — 要素は**縦積み**にする |
| 文字サイズ | タイムラインの縮小表示で読める大きさ | 小さい説明文を詰め込まない |
| 容量 | 送り先の上限を一次情報で確認(数 MB 単位のことが多い) | 実測はたいてい上限の数 % で、**問題になるのは容量ではなく比** |

**中身の決め方:**

- **アプリ名を必ず画像に入れる。** リンクカードから見出しと説明文を落として**画像とドメインだけ**を出すサービスがある。画像に文字が無いと、そこではアプリ名が 1 度も出ない。
- **1 行の説明を添える。** その画像を見る人は**そのアプリを知らない**。未説明の記号・略号・内部用語を置かない。
- **実アプリのスクリーンショット直撮りは避ける。** 縮小で文字が潰れ、差別化点が伝わらない。**要点だけを描いた専用バナー**にする。
- **描く内容がプロダクトの仕様と食い違わないようにする**(例: 特定の配置を「必ずそうなる」ように描いてしまう)。**仕様上ありえない絵は、判定ロジックのテストでは捕まらない。**

## 3. ユーザーの成果物を載せる共有画像(あれば)

プレイ結果・作成物などを画像にして共有させる場合、OG 画像とは別の制約が効く。

- **比の安全域を先に決める。** 中身の量(行数・要素数)で高さが伸びる設計だと、**日によって比が動き、いつか帯を外れる。** 「今は入っている」で守らない。**正方形(1:1)にすると比が中身によらず一定になり、主要サービスの全表示帯の内側に入る**ので、特別扱いが要らなくなる。
- **比のために中身を縮めない。** 文字が読めなくなったら画像の存在理由が消える。**辺を中身に合わせて伸ばす**側で解く。
- **辺の下限を定数だけで持たない。** 文言の長さで必要幅が変わるので、**文字を実測して下限を出す。**
- **配色は表示画面の「ライトテーマの写し」で固定する。** 画像は受け手の環境で見るものなので、**端末のダークモードに追従させない。**
- **画像を含むクリップボード書き込みは、ユーザー操作と同じターンで開始する。** 一部ブラウザは `await` を挟むと拒否するので、Blob を `Promise` のまま渡す形を崩さない。**この経路は自動テストで守りにくい**(生成が遅い環境で拒否される)ので、**E2E は「保存」側の分岐で実物を取る。**
- **文言は最小幅(320px 相当)で 1 行に収める。** 画像やカードに重ねて出す UI では、行が増えると成果物が隠れる。

## 4. ファビコン

- **ベクター 1 枚を正本にして、そこから多サイズを機械生成する**(`favicon.ico` の 16/32/48・`apple-touch-icon` 180・PWA 用 512・検索用 192 等)。**手描きの派生を複数持たない。**
- **検索結果に出したいならラスタ形式が要る**(対応形式にベクターが入っていないことがある)。宣言は **ラスタ → ベクター(`sizes="any"`)の順**で両方置く。
- **小サイズで潰れないか実物で確認する。** 細い線・多い要素はタイルサイズで消える。
- **ロゴを描き直したら生成スクリプトを流し直す**(生成物はコミットする)。この対応漏れは画面上で気づけないので、**AGENTS.md の地雷リストに 1 行**。

## 5. 生成パイプラインの作り方(3 つとも共通)

**画像は手でエクスポートせず、リポジトリ内のスクリプトで作る。**

- **実装手段**は「HTML を組んで headless ブラウザでスクリーンショット」か「Canvas を直接描く」。前者は CSS で作り込める・E2E 用のブラウザを流用できる、後者は依存が軽い。**アプリ本体が既に Canvas 描画を持っているなら後者に寄せると配色・レイアウトを共有できる。**
- **文字列(アプリ名・タグライン・URL)は単一のソースから import する。** 生成スクリプトに直書きしない。**アプリ層を import できないレイヤ制限があるなら、ブランド定数をアプリ層の外(共有モジュール)に置く** — 特定ファイルだけリントの例外にする手は、たいてい実際には通らない。
- **出力はコミットし、生成スクリプトは配布物に混ぜない。**
- **レイアウトの機械検査を 1 つ入れる**(「全要素が安全域に収まる」等のアサート)。**見た目そのものは人間の目でしか判定できない**ので、**生成物のパスを添えて「目視確認をお願いします」と報告する。**
- **実際にカードがどう出るかは投稿するまで分からない。** クロップの端・キャッシュの効き方は一次情報で確認できないことが多い。**「未確認」と明記して渡す。**

## やらないこと(逆戻りガード)

- **閲覧者の言語で OGP 画像を自動切替しようとする**(§0-2)。
- **実行時に書き換えた `<meta>` が SNS カードに出ることを期待する**(§0-1)。
- **画像パラメータ付きの共有 intent を探し続ける**(§0-3)。
- **「静的ホスティングだから URL ごとの OGP は不可能」と説明する**(§0-5)。
- **OG 画像を横並びレイアウトで組む**(正方形クロップで両方切れる)。
