# web-visual-check — 見た目と実挙動をエージェント自身で確認する

フレームワーク・ホスティング先を問わず共通。公開後の確認は [web-deploy](../web-deploy/SKILL.md)、共有画像の中身は [web-share-assets](../web-share-assets/SKILL.md)。

---

## 0. 最初に捨てる思い込み

**「GUI の無い環境(WSL・コンテナ・CI)だから画面は確認できない」は誤り。** headless Chromium は**管理者権限なしで導入・起動でき**、実際の描画・実際のキーボード入力・スクリーンショットまで取れる。**「見た目は実機確認待ち」で丸ごと投げない。**

境界は次のとおり。**できない側だけを「実機確認待ち」として報告する。**

| エージェントが確認できる | 実機でしか確認できない |
|---|---|
| 描画・レイアウト・任意のビューポート幅での崩れ | 実機のフォント・DPI・**OS のダークモード**の見え方 |
| 実際のキーボード入力・フォーカス移動・スクロール有無 | **タッチ操作**(デバイスエミュレーションでは閉じない) |
| **ブラウザ内部の IME 経路**(§3) | **OS の IME 固有部分**(変換候補の選択・確定キー・ソフトキーボードそのもの) |
| コンソールエラー・ネットワーク失敗 | **配信レイヤの挙動**(キャッシュ・圧縮 → [web-deploy](../web-deploy/SKILL.md)) |
| Canvas / ダウンロード生成物の実物 | **SNS カードの実際の見え方**(投稿するまで分からない) |

## 1. 導入と起動

**既定は Playwright + headless Chromium。** ブラウザ同梱でシステム依存を足さずに入り、CDP セッション(§3)をそのまま開けるのが理由。既に Puppeteer が入っているならそれで代替できる(CDP はどちらでも使える)。

```bash
npx playwright install chromium   # 管理者権限は不要(`--with-deps` を付けると要るが、付けなくても起動できる)
```

- **ライブラリの版は厳密固定する(`^` を付けない)。** ブラウザのビルド番号がライブラリの版に紐づくので、緩いと**キャッシュ済みブラウザと食い違って CI だけ落ちる。**
- **サーバはテストランナーに起動させ、実行後に必ず落とす。エージェントが dev / preview サーバを立てない。**
- **見るのはビルド成果物**(dev サーバではなく本番と同じ配信物)。**フレームワークで変わるのはこの 1 行だけ** — 残りは HTTP の URL に対する操作なので共通。

```ts
// playwright.config.ts
webServer: {
  // Vite:  npm run build && vite preview --host 127.0.0.1 --port 4318 --strictPort
  // Next:  next build && next start -H 127.0.0.1 -p 4318
  // 静的:  npx http-server dist -a 127.0.0.1 -p 4318
  // 他言語: rails s -b 127.0.0.1 -p 4318 / manage.py runserver 127.0.0.1:4318
  command: '<上記のいずれか>',
  url: 'http://127.0.0.1:4318',
  reuseExistingServer: false,   // 既定は true。**ユーザーが立てた古いビルドに黙って相乗りする**
},
```

- **ポートはユーザーが使う dev / preview と別にする。** `strictPort` で、埋まっていれば失敗させる。
- **bind 先は `127.0.0.1` を明示する。** 既定の `localhost` は環境によって IPv6 に解決され、**CI だけ**タイムアウトする。**ポーリング先と bind 先の表記を揃える。**

## 2. 機械で見るもの / 目視に回すもの

**スクリーンショットは主張ではない。撮っただけでは何も守れない。** 崩れの多くは**数値の不変条件**にできる。

```ts
// 例: 画面がスクロールしないこと(1px の丸めは許容)
const o = await page.evaluate(() => ({
  y: document.documentElement.scrollHeight - document.documentElement.clientHeight,
  x: document.documentElement.scrollWidth - document.documentElement.clientWidth,
}));
expect(o.y, `${where}: 縦にスクロールしている`).toBeLessThanOrEqual(1);

// 例: 要素が可視領域(or 別の器)に収まっていること
const box = await page.getByTestId('main').boundingBox();
expect((box?.y ?? 0) + (box?.height ?? 0)).toBeLessThanOrEqual(viewport.height - inset + 1);
```

- **アサートに載せる**: スクロールの有無、要素の `boundingBox()` の収まり、**コンソールエラー 0 件**、失敗したリクエスト 0 件、要素の可視 / 不可視。**メッセージに「どの画面幅で・どの対象が」を必ず入れる**(全幅で回すと、どのケースで落ちたか分からなくなる)。
- **目視に回す**: 配色・余白・字面・情報の詰まり具合。**フルページのスクリーンショットを固定ディレクトリへ吐き、報告にパスを列挙して「目視をお願いします」と書く。**
- **ビューポートは複数回す。** 最小幅(320〜360)・標準・広い幅。**崩れは最小幅で出る。**
- **アニメーション中に撮らない**(`animations: 'disabled'` 相当)。撮るタイミングで絵が変わると差分が信用できない。
- **スクリーンショットは gitignore する。** 生成物であって仕様ではない。

## 3. CDP — 通常 API では届かない経路

**ここが headless ブラウザの本当の価値。** どのラッパでも `CDPSession` を開けば同じことができる。

**① IME(日本語・中国語・韓国語入力)**

```ts
const cdp = await page.context().newCDPSession(page);
await cdp.send('Input.imeSetComposition', { text: 'ｇ', selectionStart: 1, selectionEnd: 1 }); // 未確定
await cdp.send('Input.insertText', { text: 'が' });                                            // 確定
await cdp.detach();
```

- **`keyboard.type` は IME を通らない。** これで「日本語が打てる」と判断しない。
- **`compositionstart` / `compositionend` を手で `dispatchEvent` する版では捕まらない不具合がある**(未確定文字列を横から書き換えるとブラウザが変換を打ち切る、等)。**IME 周りを触ったら CDP 版を必ず通す。**
- **確定文字列は 1 文字とは限らない**(「きゃ」「がっこう」)。1 文字前提の実装を書かない。

**② 低速端末の再現**: `Emulation.setCPUThrottlingRate`(4 倍程度)。**枚数・件数に対して超線形に伸びる描画**は、これを掛けないと手元では気づけない。**実機ではない**ので、数値は「代用」と明記する。

**③ ソフトキーボード**: 実物は出せない。**アプリ側が `visualViewport` から書く値(CSS 変数・属性)をテストから注入して、レイアウト側だけを見る。** 測る側は単体テストで別に守る。**「測定」と「描画」を分けると両方とも自動化できる。**

**④ 印刷レイアウト**: `page.pdf({ format: 'A4', printBackground: true })` で出す。**中身を目で見るには PDF ビューア入りのブラウザ本体を指定して起動する**(既定の headless shell には PDF ビューアが無く、`file://` で開いても撮れない)。

**⑤ 生成ファイルの実物**: ダウンロードイベントを待って保存する。**Canvas 描画や画像生成は jsdom では実体が出ない**ので、実物が取れるのはここだけ。

## 4. 検証が嘘をつくのを避ける

- **落ちたら実装を疑う前にマシンの負荷を疑う。** `uptime` の load average がコア数を超えていたら並列度を下げて流し直し(`--workers=1`)、**単体でも落ちるかで切り分ける**。並列ランナーは負荷が高いと**実行のたびに違うファイルが落ちる**。**環境起因ならその旨を報告に明記する。**
- **`sleep` で待たない。** 状態(要素の可視・属性の値)を待つ。**effect で入るフォーカスは描画完了と同時ではない**ので、フォーカスも待つ。
- **状態は「表示用の値」ではなく「真の状態」を読む。** 入力欄の `value` は IME 変換中だけ未確定文字列になる、といったズレがある。**テスト用の属性(`data-*`)に真の状態を出して、そちらを読む。**
- **文言をテストに書かない。** i18n カタログが正本で、2 か所目を作らない。**`data-testid` で当てる。**

## 5. E2E に残すもの / 残さないもの

**フルの検証は CI の仕事。** ローカルで流すのは「**コードを読んでも壊れに気づけないもの**」だけに絞る。

**必ず自動テストに残す(消すと壊れても気づけない):**

- **CSS だけで成立している挙動**(スクロールしない・器に収まる・幅で畳まれる)。レビューでは絶対に見つからない。
- **IME 経路**(§3-①)。
- **壊れても画面が変わらないもの**(解析ビーコン・所有権確認タグ・構造化データ)。

**残さない:**

- **クリップボードへの画像書き込み。** ユーザー操作と同じターンでの書き込みを要求する実装があり、**生成が遅い環境ではブラウザに拒否されて CI だけ落ちる。** 代わりに**「保存(ダウンロード)」側の分岐で実物を取る。**
- **見た目そのものの差分**(ピクセル比較)。フォント差で環境ごとに落ちる。**不変条件 + 目視**に分ける。
- **一度きりの調査**(性能計測・印刷確認)。使い捨てのスクリプトで測り、**数値と手順を決定記録に残してコードは残さない。**

---

## 6. 報告のしかた

- **「流したもの / 流していないもの」を必ず書く。** 「テストは流していない。CI で見る」は可、**黙って省くのは禁止。**
- **スクリーンショットのパスを列挙し、目視してほしい点を 1 行添える。**
- **§0 の右列に当たるものは「実機確認待ち」と明記する。** 確認できたものまで実機待ちにしない(逆も同じ)。
- **CSS・レイアウトの変更で最小幅の確認を省いたら、それも書く。**

## やらないこと(逆戻りガード)

- **「GUI が無いので見た目は確認できません」と答える**(§0)。
- **dev / preview サーバをエージェントが立てる**(§1)。ビルドまでで止め、コマンドと URL を渡す。
- **`reuseExistingServer` を既定のままにする**(§1。古いビルドを黙ってテストする)。
- **`keyboard.type` で IME 入力を確認したことにする**(§3-①)。
- **スクリーンショットを撮っただけで「確認した」と報告する**(§2)。
- **落ちたテストを、負荷を確かめずに実装のせいにする**(§4)。
